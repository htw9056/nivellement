Nivellement – Handbuch

@VERSION@   © Dipl.-Ing. (FH) Stefan Klein  ·  MIT-Lizenz

Nivellement wertet geometrische Nivellements klassisch aus, also ohne Ausgleichung. Für jede Nivellementlinie wird der Abschlussfehler ermittelt, gegen eine Fehlergrenze geprüft und auf die Aufstellungen verteilt. Die berechneten Höhen werden in einer Höhendatei des Projekts gespeichert und bei Mehrfachbestimmungen gemittelt oder verglichen.

Arbeitsweise und Dateiformate orientieren sich an dem früheren Programm NIGRA. Nivellement ist jedoch ein eigenständiges, unabhängig entwickeltes Programm ohne Programmcode oder Texte von NIGRA; NIGRA ist ein Produkt von Kurt Andrä, eine Verbindung besteht nicht. Vorhandene NIGRA-Projekte (Stapeldatei .NIG, Höhendatei .MDB, Projekt.xml) können direkt weiterverwendet werden.

1. Schnellstart

  1. Datei → Neues Projekt: Ordner und Namen der Stapeldatei wählen, z. B. Baustelle.NIG. Ein vorhandenes Projekt öffnen Sie mit Datei → Projekt öffnen.
  2. Im Register Kopfdaten Ort, Auftrag, Beobachter, Nivellier usw. eintragen. Sie erscheinen später im Protokollkopf.
  3. Im Register Berechnung Fehlerklasse, Mittelbildung, Verteilung und Dezimalstellen einstellen.
  4. Digital-Niv → Rohdaten (GSI / DAT) → Stapeldatei: die Messdateien des Digitalnivelliers wählen. Jede Linie wird als eigenes Nivellement mit fortlaufender Berechnungsnummer an die Stapeldatei angehängt.
  5. Im Register Stapeldatei die Messdaten kontrollieren und bei Bedarf korrigieren (Punktnummern, Kopfdaten).
  6. Im Register Höhenverzeichnis die Festpunkte eingeben oder mit Import ASCII einlesen. Festpunkte erhalten die Berechnungsnummer 999999.
  7. Messdaten prüfen und anschließend Stapelberechnung starten.
  8. Das Ergebnis erscheint im Register Protokoll und wird als <Projekt>_Protokoll.txt gespeichert. Die neuen Höhen stehen im Höhenverzeichnis.

Alle Einstellungen werden automatisch gespeichert. Ein neues Projekt übernimmt die Einstellungen und Kopfdaten des zuletzt bearbeiteten Projekts.

Dateien auswählen

Die Knöpfe ... öffnen unter Windows den gewohnten Windows-Dateidialog. Dort kann ein kopierter Ordner- oder Dateipfad in die Adressleiste oder in das Feld Dateiname eingefügt werden (Strg+V).

Alternativ fügen Sie einen Pfad direkt in das Feld im Programm ein, z. B. mit Als Pfad kopieren aus dem Windows-Explorer. Anführungszeichen werden dabei automatisch entfernt. Im Feld Projekt / Messdatei wird das Projekt mit Enter oder beim Verlassen des Feldes geöffnet.

3. Projekte und Dateien

Ein Projekt ist ein Ordner mit einer Stapeldatei. Das Programm legt daneben weitere Dateien an, die alle mit dem Projektnamen beginnen:

DateiInhalt
<Projekt>.NIGStapeldatei mit allen Messdaten (Textdatei, Zeichensatz ANSI wie bei NIGRA)
<Projekt>_Hoehen.csvHöhendatei (Semikolon-getrennt, in Excel lesbar)
<Projekt>_Protokoll.txtBerechnungsprotokoll
<Projekt>_Einstellungen.propertiesEinstellungen des Projekts

Statt einer Stapeldatei kann auch eine GSI- oder DAT-Datei direkt als Messdatei gewählt und berechnet werden. Die Höhendatei heißt dann ebenfalls <Messdatei>_Hoehen.csv. Für eine dauerhafte Bearbeitung ist die Stapeldatei aber besser geeignet, weil sich die Messdaten dort korrigieren lassen.

Im Feld Höhendatei kann eine andere Höhendatei angegeben werden, z. B. eine gemeinsame Datei für mehrere Projekte. Bleibt es leer, wird <Projekt>_Hoehen.csv verwendet.

4. Rohdaten übernehmen

Mit Digital-Niv → Rohdaten (GSI / DAT) → Stapeldatei werden eine oder mehrere Messdateien umformatiert und an die Stapeldatei angehängt. Das Format wird automatisch erkannt. Jede Linie erhält

  • die nächste freie Berechnungsnummer,
  • die Kopfdaten aus dem Register Kopfdaten,
  • Mittelbildung, Fehlerklasse, erlaubte Differenz und Dezimalstellen aus dem Register Berechnung.

Eine im Gerät gespeicherte Anfangshöhe wird als Kommentarzeile xH <Punkt> <Höhe> mitgeführt. Sie wird nur verwendet, wenn der Anfangspunkt weder in der Festpunkt- noch in der Höhendatei steht.

5. Die Stapeldatei

Die Stapeldatei (.NIG) ist eine Textdatei mit festem Spaltenaufbau. Sie enthält beliebig viele Nivellements hintereinander. Jedes Nivellement besteht aus einem Steuerdatenblock und einem Messdatenblock; beide enden mit einer Zeile, die mit E beginnt. Maßgebend ist das Zeichen in Spalte 1:

Spalte 1Bedeutung
CTitel (erscheint im Protokollkopf)
BBerechnungsnummer
KKopf- und Parameterzeilen (genau 20 Stück, Reihenfolge siehe unten)
EEnde des Steuerdatenblocks bzw. des Messdatenblocks
DMessdatensatz, Mittelbildung wie im Steuerdatenblock
0 1 2 3Messdatensatz mit eigener Mittelbildung für diesen Punkt
jedes andere Zeichen (z. B. x, *)Kommentar – die Zeile wird ignoriert

Eine Messzeile lässt sich vorübergehend ausblenden, indem man das D in Spalte 1 durch ein x ersetzt.

Kopf- und Parameterzeilen (K)

Nr.InhaltNr.Inhalt
1, 2Ort (2 Zeilen)13Nivellementart und Beobachtungsfolge, z. B. 00
3, 4Auftrag (2 Zeilen)14Anzahl Lattenteilungen bzw. Ablesungen (1 oder 2)
5Linie/Zug15Lattenkonstante (bei 2 Teilungen)
6Datum16Erlaubte Differenz bei 2 Ablesungen [0,1 mm]
7Wetter17Lattenteilung: 1 = cm, 0.5 = ½ cm
8Beobachter18Berechnung mit Strecken: 1 = ja, 0 = nein

Der Wert steht in den Spalten 2–20, ab Spalte 22 folgt ein erläuternder Text, der nicht ausgewertet wird.

Die E-Zeile des Steuerdatenblocks enthält: Spalte 2 = Mittelbildung (0–3), Spalte 3 = Fehlerklasse (1–4), Spalte 4 = Maßeinheit (m). Beispiel: E13m bedeutet Mittelbildung „neu“, Fehlerklasse 3, Meter.

Nivellementart (1. Stelle von Zeile 13): 0 = Nivellement mit Zwischenblicken, 1 = Streckennivellement, 4 = Linienausgleichung, 5 = Instrumentenprüfung. Die 2. Stelle gibt die Beobachtungsfolge an (0 = RV bzw. RRVV, 2 = RVVR, 4 = RVRV, 5 = VRRV), ein angehängtes a steht für alternierend.

Beispiel:

Innerhalb ihres Spaltenbereichs dürfen die Werte frei stehen. Das Spaltenlineal über dem Editor und die Anzeige „Zeile, Spalte“ unten helfen beim Ausrichten.

Bei zwei Ablesungen je Ziel (2 Lattenteilungen, RRVV, RVVR) folgen die beiden Ablesungen eines Ziels unmittelbar aufeinander. Sie werden gemittelt und verglichen.

Messdaten prüfen

Die Prüfung (Register Stapeldatei oder Berechnung) meldet ohne zu rechnen: fehlende oder unvollständige Steuerblöcke, ungültige Zahlen, Vorblicke ohne Rückblick, Aufstellungen ohne Vorblick, unterbrochene Linien (Rückblickpunkt ungleich vorherigem Vorblickpunkt) und fehlende Strecken.

7. Rechenweg und Formeln

Bezeichnungen: R = Rückblick, V = Vorblick, Z = Zwischenblick (bei zwei Ablesungen jeweils das Mittel), sR, sV = Zielweiten, t = Lattenteilung (1 bzw. 0,5), n = Anzahl der Aufstellungen, i = Nummer der Aufstellung.

Höhenunterschied je Aufstellung

dhi = (Ri − Vi) · t

Abschlussfehler

w = (HE − HA) − Σ dhi    (Soll − Ist)

Bei einer Schleife ist HE = HA. Ein positiver Abschlussfehler bedeutet, dass die gemessenen Höhenunterschiede zu klein sind; die Verbesserungen sind dann positiv.

Verteilung

Streckenproportional (Standard, wenn alle Zielweiten vorhanden sind):

vi = w · (sR,i + sV,i) / Σ(sR + sV)

Nach Anzahl der Rück- und Vorblicke (oder wenn Zielweiten fehlen):

vi = w / n

Strecken zu Zwischenblicken gehen nicht in die Verteilung ein.

Höhen der Wechselpunkte

HV,i = HR,i + dhi + vi

Höhen der Zwischenpunkte

Ein Zwischenpunkt erhält den Anteil der Verbesserung seiner Aufstellung, der auf den Weg vom Rückblickpunkt bis zum Instrument entfällt:

HZ = HR,i + (Ri − Z) · t + vi · sR,i / (sR,i + sV,i)

Bei Verteilung nach Anzahl der Blicke wird statt des Streckenverhältnisses ½ verwendet.

Zwei Ablesungen je Ziel

Differenz der beiden Ablesungen eines Ziels (im Protokoll Spalte „d“, Einheit 0,1 mm):

d = A1 − A2 − Lattenkonstante

Bei Vor- und Zwischenblicken folgt nach einem Schrägstrich die Standpunktdifferenz dR − d. Überschreitet ein Wert die erlaubte Differenz, wird er mit *** markiert.

Kontrolle (erweitertes Protokoll)

(ΣR − ΣV) · t + Σv − (HE − HA) = 0

Rundung

Gerundet wird nur bei der Ausgabe, und zwar geodätisch: Liegt ein Wert genau in der Mitte, wird zur geraden Ziffer gerundet (109.0625 → 109.062, 109.0635 → 109.064). Das entspricht NIGRA.

8. Fehlerklassen und Fehlergrenzen

Für jede der vier Fehlerklassen wird in der Programmkonfiguration eine Formel für den zulässigen Abschlussfehler F in mm hinterlegt. R ist der Messweg in km, also die Summe aller Zielweiten von Rück- und Vorblicken.

KlasseVorgabe
11 + 3*Sqrt(R)
22 + 3*Sqrt(R)
32 + 5*Sqrt(R)
43 + 8*Sqrt(R)

Die Vorgaben sind Beispiele. Bitte tragen Sie die für Ihre Arbeiten geltenden Werte ein, z. B. nach den Vorschriften Ihres Auftraggebers.

Erlaubt sind Zahlen, R, + - * / ^, Klammern sowie Sqrt() (Quadratwurzel) und Abs() (Betrag). Beispiele: 2 + 3*R, 2 + 3*Sqrt(R/2), 1.5 + 2.5*R^0.5. Komma und Punkt sind als Dezimalzeichen zulässig.

Wird die Fehlergrenze überschritten, steht im Protokoll *** hinter dem erlaubten Fehler und die Linie wird als Fehler gezählt. Mit dem Schwellfaktor erhalten Sie zusätzlich eine Warnung, wenn ein Teil der Fehlergrenze überschritten ist: Bei 0.5 wird gewarnt, sobald |w| größer als die halbe Fehlergrenze ist. Der Wert 1 schaltet diese Warnung aus.

9. Höhendatei und Mittelbildung

Die Höhendatei enthält je Punkt:

FeldBedeutung
Punkt-Nr.Punktnummer
HöheHöhe in m (intern mit 8 Nachkommastellen gespeichert)
BerNr.Berechnungsnummer der letzten Bestimmung; 999999 = Festpunkt
Diff.Mittelungsdifferenz in mm: neue minus bisherige Höhe
ABAnzahl der Bestimmungen
Datum, Bemerkungfrei

Festpunkte (BerNr. 999999 oder aus der Festpunktdatei) werden durch eine Berechnung nie verändert. Wird ein Festpunkt erneut bestimmt, erscheint die Differenz im Mittelbildungsprotokoll.

Mittelbildung

WertNameWirkung, wenn der Punkt bereits in der Höhendatei steht
0mittelnH = (Halt·AB + Hneu) / (AB + 1); AB wird um 1 erhöht
1neudie neue Höhe ersetzt die alte, AB = 1
2vergleichendie alte Höhe bleibt, die Differenz wird protokolliert
3ohneweder speichern noch vergleichen

Neue Punkte werden bei 0, 1 und 2 gespeichert. Die Mittelbildung gilt für die ganze Linie (E-Zeile des Steuerdatenblocks) und kann für einzelne Punkte geändert werden, indem in der Stapeldatei das D in Spalte 1 durch 0, 1, 2 oder 3 ersetzt wird. Im Protokoll steht dann hinter der Punktnummer ein Kennbuchstabe: m = mitteln, n = neu, a = vergleichen (alt), o = ohne.

Das Mittelbildungsprotokoll am Ende der Berechnung listet alle mehrfach bestimmten Punkte mit ihrer Differenz. Differenzen über der Grenze für Mehrfachbestimmungen werden mit *** markiert; bei „mitteln“ wird der Punkt trotzdem gemittelt.

Wenn ein Projekt mit „mitteln“ ein zweites Mal vollständig berechnet wird, würde jeder Punkt erneut gemittelt. Kreuzen Sie deshalb vor einer Neuberechnung Neupunkte vorher löschen an.

11. Das Protokoll

Für jede Berechnung enthält das Protokoll:

  • den Kopf mit Firma, Programmversion, Datum und Projekt,
  • Titel, Berechnungsnummer und Kopfdaten,
  • Lattenteilung, Beobachtungsfolge, ggf. Lattenkonstante und erlaubte Differenz,
  • Mittelbildung, Anschlusspunkte mit Herkunft der Höhen, Linienart,
  • Abschlussfehler und erlaubten Fehler F mit Fehlerklasse,
  • die Messwerte mit Strecke, Rück, Zwischen, Vor, Differenzen d, Höhe und Punkt-Nr.,
  • die Summen der Strecken (gesamt, Rückblicke, Vorblicke),
  • Fehler (***) und Hinweise.

Am Ende folgen die Gesamtsumme aller Strecken (ohne Zwischenblicke), der größte Abschlussfehler mit seiner Berechnungsnummer, die Anzahl der Fehler und gegebenenfalls das Mittelbildungsprotokoll.

Das erweiterte Protokoll zeigt zusätzlich je Punkt den Höhenunterschied dh und die Verbesserung v in mm sowie die Rechenprobe.

Alle Zahlen werden mit Dezimalpunkt ausgegeben. Das Protokoll ist eine UTF-8-Textdatei und kann mit jedem Editor geöffnet und gedruckt werden.

12. Drucken

Gedruckt wird der Inhalt des aktuellen Registers:

RegisterAusdruck
Protokoll (und alle übrigen Register)Berechnungsprotokoll; jede Berechnung beginnt auf einer neuen Seite
StapeldateiMessdaten (Inhalt der Stapeldatei)
Höhenverzeichnisalle angezeigten Punkte in der aktuellen Sortierung (ein gesetzter Filter wirkt auch auf den Ausdruck)

Aufruf über Datei → Drucken (Strg+P), Datei → Druckvorschau oder die Knöpfe Drucken und Druckvorschau in den Registern. In der Vorschau kann geblättert und von dort gedruckt werden.

Jede Seite (DIN A4 hochkant) erhält

  • oben links die Firma aus der Programmkonfiguration, den Titel des Ausdrucks und das Projekt,
  • oben rechts das eigene Logo,
  • unten Programmversion, Druckdatum und „Seite x von y“.

Die Schriftgröße wird so gewählt, dass auch das erweiterte Protokoll in voller Breite auf die Seite passt. Ist beim Öffnen eines Projekts schon eine Protokolldatei vorhanden, wird sie angezeigt und kann ohne neue Berechnung gedruckt werden.

Logo

Im Register Programmkonfiguration unter Logo im Druckkopf eine Bilddatei wählen (PNG, JPG, GIF oder BMP). Die Höhe legt die Größe im Ausdruck fest (Vorgabe 20 mm); mit max. Breite lässt sich ein sehr breites Logo zusätzlich begrenzen (0 = keine Begrenzung). Das Seitenverhältnis bleibt immer erhalten. Unter den Feldern wird das Logo zur Kontrolle angezeigt. Am besten eignet sich ein PNG mit weißem oder transparentem Hintergrund und etwa 600 Pixel Breite.

PDF erzeugen: Im Druckdialog den Drucker Microsoft Print to PDF wählen (in Windows 10 und 11 enthalten).

13. Kopfdaten

Die Kopfdaten werden bei der Übernahme von Rohdaten in die Stapeldatei geschrieben und bei der direkten Berechnung von GSI/DAT-Dateien in das Protokoll übernommen. In der Stapeldatei stehen einzeilige Angaben in 19 Zeichen; Ort, Auftrag und Bemerkung dürfen 38 Zeichen lang sein und werden auf zwei Zeilen verteilt. Der Projekttitel wird zur C-Zeile und erscheint über jeder Berechnung.

Kopfdaten bereits übernommener Nivellements ändern Sie direkt in der Stapeldatei.

15. Speichern der Einstellungen

Alle Einstellungen werden automatisch gespeichert, sobald sie geändert werden.

EbeneDateiInhalt
Programm.nivellement.properties im Benutzerordner (Windows: C:\Users\<Name>)Programmkonfiguration, zuletzt verwendete Einstellungen, letztes Projekt, Fenstergröße und -lage, letzter Ordner
Projekt<Projekt>_Einstellungen.propertiesalle Einstellungen des Projekts einschließlich Kopfdaten, Festpunkt- und Höhendatei
  • Ein neues Projekt übernimmt alle Einstellungen des zuletzt bearbeiteten Projekts – außer Festpunkt- und Höhendatei.
  • Beim Öffnen eines Projekts werden seine eigenen Einstellungen wiederhergestellt.
  • Hat ein Projekt noch keine eigenen Einstellungen, aber eine NIGRA-Projekt.xml im Ordner, werden die NIGRA-Einstellungen übernommen.
  • Beim Programmstart wird das zuletzt bearbeitete Projekt geöffnet.
  • Gespeichert werden alle Felder, Auswahlen und Haken. Manuelle Anfangs- und Endhöhe sowie Berechnungsnummer von–bis gehören nur zum jeweiligen Projekt und werden nicht in ein neues Projekt übernommen.
  • Halb eingegebene oder ungültige Zahlen verhindern das Speichern der übrigen Einstellungen nicht; sie werden erst beim Berechnen gemeldet.

Die Rechenweise wurde mit realen NIGRA-Projekten verglichen; Höhen, Abschlussfehler, Fehlergrenzen, Mittelbildung und Höhendatei stimmen überein. Unterschiede gibt es nur in der Darstellung des Protokolls.

Tipp für die Umstellung: Kopieren Sie ein NIGRA-Projekt in einen Testordner, öffnen Sie dort die .NIG, übernehmen Sie die .MDB, kreuzen Sie „Neupunkte vorher löschen“ an und vergleichen Sie das neue Protokoll mit der NIGRA-Ausgabe (.BER).

17. Aufruf in der Konsole

Unter Windows mit NivellementKonsole.exe, sonst mit java -jar Nivellement.jar. Ohne Argumente startet die Oberfläche. Es gelten die gespeicherten Projekteinstellungen; Optionen auf der Kommandozeile haben Vorrang.

NivellementKonsole.exe <Messdatei .nig|.gsi|.dat> [Optionen]

  -f <Datei>        Festpunktdatei (je Zeile: Punkt Höhe)
  -hd <Datei>       Höhendatei (Standard: <Projekt>_Hoehen.csv)
  -v z|a            Verteilung streckenproportional (z) oder nach Anzahl der Blicke (a)
  -k 1..4           Fehlerklasse
  -m 0..3           Mittelbildung 0=mitteln 1=neu 2=vergleichen 3=ohne
  -n 2..5           Dezimalstellen der Höhen
  -ha <m> -he <m>   Anfangs-/Endhöhe manuell (erste Linie)
  -neu              Neupunkte vorher aus der Höhendatei löschen
  -x                erweitertes Protokoll
  -von <n> -bis <m> nur Berechnungsnummern n bis m
  -a                Protokoll anhängen statt alte Berechnung löschen
  -p                Messdaten nur prüfen
  -u <Datei>        GSI/DAT umformatieren und an die Stapeldatei anhängen
  -mdb <Datei>      NIGRA-Höhendatei (.MDB) übernehmen
  -asc <Datei>      Höhenverzeichnis (ASCII) übernehmen
  -export <Datei>   Höhenverzeichnis als ASCII ausgeben
  -h                Hilfe

Beispiele:

NivellementKonsole.exe Baustelle.NIG -u Linie1.gsi -u Linie2.dat
NivellementKonsole.exe Baustelle.NIG -neu
NivellementKonsole.exe Baustelle.NIG -von 5 -bis 8 -a
NivellementKonsole.exe Baustelle.NIG -export Hoehen.ASC -n 3

19. Häufige Fragen

Warum ändern sich die Höhen bei jeder Neuberechnung leicht?
Mit Mittelbildung „mitteln“ wird jede Berechnung mit den bereits gespeicherten Höhen gemittelt. Vor einer vollständigen Neuberechnung „Neupunkte vorher löschen“ ankreuzen.

Ich habe Werte in der Stapeldatei geändert, die Berechnung zeigt aber das Alte.
Der Editor speichert vor jeder Prüfung und Berechnung automatisch. Wurde die Datei außerhalb des Programms geändert, im Register Stapeldatei auf Neu laden klicken.

Kann ich die Höhendatei in Excel bearbeiten?
Ja, sie ist eine Semikolon-getrennte CSV-Datei. Das Programm sollte dabei nicht gleichzeitig dieselbe Datei geändert haben.

Wie kann ich ein einzelnes Nivellement neu rechnen?
Berechnungs-Nr. von und bis auf diese Nummer setzen und „Alte Berechnung löschen“ ausschalten, wenn das bisherige Protokoll erhalten bleiben soll.

Windows meldet beim ersten Start „Der Computer wurde durch Windows geschützt“.
Das Programm ist nicht digital signiert. Auf „Weitere Informationen“ und dann „Trotzdem ausführen“ klicken.

Wo finde ich den Quelltext?
Das Programm ist Open Source (MIT-Lizenz) und auf GitHub veröffentlicht.
